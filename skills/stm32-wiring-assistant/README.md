# STM32 硬件与接线助手：完整使用说明

这是一个供 Codex 使用的 Skill，用来设计或审查 STM32 项目的接线和引脚分配，并用中文逐根解释连接。实际结论以当前器件、工程代码和实测为准。

## 文件

- [SKILL.md](SKILL.md)：Skill 的主要工作流程。
- [references/hardware-baseline.md](references/hardware-baseline.md)：用户曾使用的器件与接线，属于历史参考，不保证仍为当前状态。
- 本文件：安装和使用说明。

## 安装与调用

将整个 `stm32-wiring-assistant` 目录（至少包含 `SKILL.md` 和 `references/`）复制到 Codex 的技能目录，例如 Windows 当前用户的 `C:\Users\<用户名>\.codex\skills\stm32-wiring-assistant\`。如果安装后没有识别，可重新启动 Codex。

在新对话输入：

```text
使用 $stm32-wiring-assistant，帮我检查当前项目的接线和引脚冲突。
```

也可以直接描述 STM32 接线任务，是否自动选中取决于对话环境。调用时应提供当前工程路径、实际硬件变化，并说明这一阶段是否允许修改代码。如果有多个工程副本，请明确指出正在使用的最新副本。

## 可复制的提示词

### 开始新项目

```text
使用 $stm32-wiring-assistant。
我想用现有的 STM32 和模块制作：【项目想法】。
请读取我指定的最新工程，检查硬件、引脚冲突和供电，输出逐根接线表，
用大白话讲解，并给出上电后的检查顺序。
这一阶段先不要修改代码，等我确认后再进入下一阶段。
```

### 增加一个模块

```text
使用 $stm32-wiring-assistant。
我想增加【模块名称及型号】；模块上的接口写着【接口名称】，希望实现【功能】。
请检查当前工程的引脚占用，推荐接法。型号或供电信息不足时请标注，不要猜测。
先给我接线表，暂时不要修改代码。
```

### 修改引脚

```text
使用 $stm32-wiring-assistant。
我想把【模块】的【原引脚】改到【新引脚】。
请检查 GPIO、定时器、串口、I²C、SWD 和代码是否冲突，列出需要改动的接线与文件。
先告诉我结果，暂时不要修改工程。
```

如果允许直接改工程，可明确说：“确认无冲突后，直接修改我指定的现有工程，并报告实际编译结果。”

### 接线图与面包板布局

```text
使用 $stm32-wiring-assistant。
请根据当前工程制作接线图和面包板布局示意图：
标出每个接口、开发板丝印、LED 限流电阻、按键触点、I²C 上拉、
舵机独立供电与共地；图与代码的引脚必须一致，并用大白话逐根解释。
不确定的器件针序和面包板孔位请明确说明。
```

布局示意图展示器件的安排；如果没有核对实物针距、针序和面包板连通关系，不能把图上的每个孔视为已验证的准确接线位置。

### 接线后的逐项验证

```text
使用 $stm32-wiring-assistant。
我已经按接线表连接完成，请根据当前工程设计检查顺序。
每一步列出操作、预期现象和失败时先查什么；区分编译结果与实体板测试结果。
```

### 核对图纸和代码

```text
使用 $stm32-wiring-assistant。
请对照当前 Keil 工程和接线文档，检查各模块引脚是否一致。
只做检查，先不要修改；说明涉及的文件、实际代码引脚和建议处理方法。
```

## 供电示例

历史方案中，舵机信号接 PA8，舵机电源正负分别接已确认的独立 5V 电源正负，独立电源 GND 再与 STM32 GND 共地。具体电压、线序和电源能力应根据实际器件确认，不能仅凭线皮颜色推断极性。I²C 上拉应先检查模块已有电路，不能盲目叠加。

## 工程维护约定

先读取用户指定的最新工程，只修改当前需求涉及的内容，保留芯片型号、库、编译器配置和工程结构；增加源文件时检查是否需要加入 Keil 工程。无法访问或修改时，明确说明并优先提供相对路径和补丁。只有用户明确要求“打包完整工程”才生成压缩包。每次报告修改文件、实现功能、实际编译结果和待实测事项。

## 更新参考清单

当实际硬件或接线发生变化时，可以说：

```text
更新 $stm32-wiring-assistant 的硬件参考清单。
我现在把【器件】从【原接法】改成了【新接法】。
```

让助手核对当前工程和实物后，再更新 `references/hardware-baseline.md`。不同电脑上的本地工程路径需要由使用者提供。

## 验证状态

创建时使用 PyYAML 6.0.3 通过 `skill-creator` 的 `quick_validate.py`（UTF-8 模式）。曾在创建对话中按 Skill 流程检查“假设增加按钮”的场景；该检查没有修改代码、烧录或完成实体板验收。不能据此认定所有接线方案都已通过硬件验证。
