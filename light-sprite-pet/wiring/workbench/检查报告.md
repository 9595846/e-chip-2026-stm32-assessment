# 接线与固件核对报告

日期：2026-11-09。基线：`6792331efe9d0f9f09516398777d2d3947f9dce7` 的 `light-sprite-pet/`。对象：STM32F103C8T6，Keil MDK 5.34，ARMCC 5.06 update 7 build 960，STM32F10x 标准外设库；选中 **Stage6 / APP_STAGE=6**。

## 结论与边界

接线工作台实际创建并保存了 19 模块、46 连接的项目，输出可编辑 JSON、SVG、网页 PNG 与接线表。当前模型静态检查：**错误 0、警告 1、待确认信息 8**。图中几何交叉 0、重叠线段 0。自定义文件/网络检查 26 项通过，详见 [verification.json](verification.json)。

这表示已填写的模型没有触发短路、输出争用等规则，**不表示整套硬件已经可以直接上电**。蜂鸣器供电未定、实物型号/电平/上拉和电源容量未测量；IMU 与当前驱动存在需要按实物确认的兼容性条件。

主控引脚复用依据 [ST 官方 STM32F103x8/xB 数据手册 DS5319](https://www.st.com/resource/en/datasheet/stm32f103c8.pdf) 的引脚定义表：PA6/PA7 为 TIM3_CH1/2，PA8 为 TIM1_CH1，PB6/PB7 为 I2C1_SCL/SDA，PA13/PA14 为 SWDIO/SWCLK。这里仅核对本项目实际选用的功能；“芯片还能复用别的功能”不意味着它们被当前程序启用。

项目时钟配置为 HSI/2×16，CPU_HZ 为 64MHz；TIM1 在 APB2，PSC=63、ARR=19999 对应设计周期 20ms。TIM3 用于编码器，TIM1 用于舵机，两者通道没有重复分配。OLED 使用 I2C1，IMU 独立软件总线；KEY3/4 的 PB8/9 不影响本项目未重映射的 I2C1。上述为源码核对，没有示波器实测时序。

## 必须确认或处理的事项

| 编号 | 条件 / 问题 | 影响 | 可执行的确认办法 |
|---|---|---|---|
| R1 | MH-FMD VCC 电压和 I/O 兼容性未知 | 供电接错或模块反向供电；图纸不能直接作为完整可通电接线 | 查模块资料和标识，确认额定供电及 3.3V 控制兼容性。确认前整模块断开；确定后更新 VCC 网络和电气属性 |
| R2 | 实际 IMU 若返回 WHO=0x70 | 当前驱动和 `MPU DIAG` 均只接受 0x68/0x69，会报 NO_VALID_DEVICE；不能据此认定模块坏 | 用已有 `I2C SCAN` / `MPU DIAG` 记录 ACK 与 WHO，按真实芯片资料确认。若为另一型号，另行评审驱动；本次不修改固件 |
| R3 | 3.3V 供电来源、独立 5V 容量/极性尚未确认 | 棕断、舵机抖动、反接或多路输出并联 | 先空载测电压和极性；仅选择一路逻辑电源；检查电源标称及舵机动作时电压。VTref 不能默认当输出 |
| R4 | 两路 I²C 是否已有 3.3V 上拉未知 | 空闲被拉低、上升慢、超时；盲目重复补装可能过强 | 断电查板载电阻/原理图；通电确认总线高电平，必要时测上升沿；无上拉时每线补 10kΩ 到 3.3V |
| R5 | USB-TTL RXD/TXD 的真实电平未知 | 信号不兼容或影响 GPIO | 确认是 3.3V TTL，VCC 跳帽不一定控制 TXD 电平；VCC 不接；非 TTL 接口禁止直连 |
| R6 | 舵机型号、线序、3.3V PWM 门限及尾巴机械行程未核实 | 误接、无动作、堵转或抖动 | 查线序和型号，独立 5V、共地；先卸负载居中，再小幅试动。软件角度不是实测角度 |
| R7 | 编码器类型与 LED 阻值未确定 | 有源编码器供电遗漏、计数错误，或 LED 太暗/过流 | 核实无源/有源模块；用万用表辨脚与阻值，每颗 LED 单独串联电阻；不短接限流电阻 |
| R8 | 杜邦线长度、接头、面包板分段电源轨与按钮接触不确定 | 间歇性断线或供电压降 | 查通断、拉动检查插头，按钮间留空间；舵机电流走可靠电源线，传感器信号线尽量短 |

自动规则的 1 项警告对应 R1 的 VCC 未接；8 项信息分别是 4 根 I²C 线的上拉未知、蜂鸣器控制电平未知、舵机信号范围未知，以及 TTL TXD/RXD 电平未知。R2、供电容量、LED 阻值、GPIO 复用和真实针序是自动规则不能全面证明的内容，已人工补充，不能因为自动错误数为 0 就略过。

## 文档一致性与旧资料兼容

本次所读 README、原接线表与上述实际代码的核心引脚一致。旧对话其他工程曾用过 PA11/12、PB13/14 按键等，不能带入本工程；本图采用 OLED PB6/7、MPU PB10/11、KEY2 PB15、蜂鸣器 PB14。原数码管扩展图仅是参考，当前未接入，不能占用 MPU 的 PB10/PB11。

原文“MPU6050”与历史测试出现的 WHO=0x70 之间存在条件性型号不一致；没有证据证明这次使用的就是历史那块模块，所以报告列为待确认，而不是宣布板子损坏或偷偷换驱动。原文未指定蜂鸣器供电、LED 电阻值，图中继续明确未知。

## 只读扫描的局限

工作台只读扫描选择 Stage6，共读取 38 个源/头文件，记录 327 条无法自动判定的表达式/寄存器访问。它们主要涉及库内部、动态 GPIO 包装函数及寄存器配置，**不是 327 个接线故障**。完整原始结果保存在 `keil_readonly_scan.json`；扫描器未运行 C 预处理器或编译器，不能靠它保证跨文件宏和条件分支的最终状态。

涉及本图的用户源码和 `.uvprojx` 已与指定远端基线文本核对，允许换行与文件末尾空白差异；代码调用关系和资源映射另行人工核对。扫描指纹用于复核读取范围，不把扫描报告包装成新的 Keil 构建证明。
